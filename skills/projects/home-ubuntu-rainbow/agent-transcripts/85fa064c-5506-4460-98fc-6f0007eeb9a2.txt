## 기존필름 제거 관리자 데이터 연동 분석

### 1. 데이터 구조
- 테이블: `online_data`
- 필터: `data_type1 = '기존필름'`
- 주요 컬럼:
  - `n_id`: 고유 ID
  - `data_type2`: 제거 위치 (예: '전면', '측후면', '썬루프', '파노라마 썬루프')
  - `data_op1`: 가격

### 2. 관리자 페이지 (`adm/online_existing.php`)
- 조회: `data_type1 = '기존필름'` 목록 표시
- 등록: 위치(`data_type2`)와 가격(`data_op1`) 등록
  - 처리: `adm/online/online_list_update.php` (129-141줄)
- 수정: 선택 항목 가격 수정
  - 처리: `adm/ajaxUP.php` (AJAX)
- 삭제: 선택 항목 삭제
  - 처리: `adm/ajaxDel.php` (AJAX)

### 3. 유저 페이지 연동 흐름

#### 3-1. 목록 페이지 (`theme/basic/skin/board/board_02/list.skin.php`)
```php
// 387-401줄: online_data 테이블에서 기존필름 제거 위치 목록 조회
$checkItemSql = "SELECT data_type2 FROM online_data 
                 WHERE data_type1 = '기존필름' ORDER BY n_id ASC";
// 405-409줄: 체크박스로 표시 (인덱스 k 사용)
<input type="checkbox" value="1" name="e_op1[<?=$k?>]"><?=$v?>
```

#### 3-2. 작성 페이지 (`theme/basic/skin/board/board_02/write.skin.php`)
```php
// 209줄: 하드코딩된 위치 배열
$itemRemoveType = array('전면', '측후면', '파노라마 썬루프', '썬루프');

// 291-302줄: 선택된 체크박스 순회하며 가격 조회
foreach ($_POST['e_op1'] as $k => $v) {
    $removeSql = "SELECT data_op1 FROM online_data 
                  WHERE data_type1 = '기존필름' 
                  AND data_type2 = '{$itemRemoveType[$k]}'";
    $itemOp1 = sql_fetch($removeSql);
    $itemTotal += (int)$itemOp1['data_op1'];
}
```

### 4. 잠재적 문제점
- 인덱스 불일치 가능성:
  - `list.skin.php`는 DB에서 동적으로 가져온 순서로 인덱스 `$k` 생성
  - `write.skin.php`는 하드코딩된 `$itemRemoveType` 배열 인덱스 사용
  - DB 순서와 하드코딩 배열 순서가 다르면 잘못된 위치의 가격이 조회될 수 있음

### 5. 개선 제안
`write.skin.php`에서도 DB에서 동적으로 위치를 가져오거나, 체크박스에 실제 `data_type2` 값을 함께 전달해 인덱스 의존을 제거하는 것이 안전합니다.

현재 구조에서는 관리자가 `online_data`에 등록한 순서(`n_id ASC`)와 `$itemRemoveType` 배열 순서가 일치해야 정상 동작합니다.
