### 2. `트래픽 초과` 오류 원인 파악용 질문 (필수)

“트래픽 초과”라고 했는데, 이게 정확히:

- **웹호스팅사(카페24/가비아/브리즈 등)에서 띄우는 ‘월 트래픽 초과’ 안내 페이지인지**,  
- 아니면 **서버 내 웹앱(예: PHP, XE, 게시판)이 자체적으로 띄우는 커스텀 에러 페이지인지**

에 따라 해결 방법이 완전히 달라져.

가능하면:

- 브라우저에서 보이는 **오류 페이지 전체 스크린샷**이나,
- 그 페이지의 **텍스트 내용**을 복붙해서 보여줘.

그걸 봐야 “단순 호스팅 트래픽 한도 초과”인지, “서버/웹서버 설정 문제”인지 정확히 판단 가능해.

### 3. 만약 네가 SSH 접속이 되는 상황이라면, 안에서 바로 확인해야 할 것들

SSH 접속이 되는 상태라고 가정하고, 아래 명령들을 순서대로 실행해 보고 **결과를 복붙**해 줘. 그러면 내가 거기 맞춰서 정확히 어디를 손봐야 하는지까지 이어서 알려줄게.

1. **디스크 용량 확인 (용량 부족으로도 서비스 장애 발생 가능)**

```bash
df -h
```

2. **메모리 상태 확인**

```bash
free -h
```

3. **웹서버 종류 및 상태 확인 (Apache / Nginx 등)**

```bash
ps aux | egrep 'apache2|httpd|nginx' | grep -v grep
```

4. **로그 위치 후보 확인 (Apache 예시)**

```bash
ls -l /var/log
ls -l /var/log/apache2 2>/dev/null
ls -l /var/log/httpd 2>/dev/null
ls -l /var/log/nginx 2>/dev/null
```

5. (어디가 있는지 보이면) 최근 에러 로그 몇 줄:

```bash
# 예: Apache2
sudo tail -n 50 /var/log/apache2/error.log 2>/dev/null

# 예: httpd
sudo tail -n 50 /var/log/httpd/error_log 2>/dev/null

# 예: nginx
sudo tail -n 50 /var/log/nginx/error.log 2>/dev/null
```

### 2. vhost / 웹서버 설정 위치 찾기

같은 서버가 dducksuda.com을 서비스하고 있는지 확인하려면, **도메인 이름이 들어간 설정 파일**을 찾아야 해.

```bash
# Apache 계열 (Ubuntu/Debian 계열일 확률 높음)
grep -R "dducksuda.com" /etc/apache2 /etc/httpd 2>/dev/null

# Nginx일 가능성도 같이 확인
grep -R "dducksuda.com" /etc/nginx 2>/dev/null
```

- 어떤 파일에 `dducksuda.com`이 나오는지, 그 **파일 경로 + 해당 줄 몇 줄**을 복사해서 보내줘.  
  (예: `/etc/apache2/sites-enabled/dducksuda.conf` 일부 내용)

여기서 보통:

- 트래픽 제한 모듈 설정(예: `mod_evasive`, `mod_qos`, `limit_req` 등)  
- 특정 IP/시간대당 요청 수 제한  
- 다른 서버/호스팅으로 프록시/리다이렉트하는 설정  

같은 것들이 보이면, 그 부분을 같이 보고 원인 짚을 수 있어.

### 3. 에러 로그에서 직접 원인 단서 찾기

“트래픽 초과”류 문제면 **웹서버 에러 로그에 힌트**가 남아 있을 확률이 큼.

```bash
# Apache 가능성 (Ubuntu 계열)
sudo tail -n 100 /var/log/apache2/error.log 2>/dev/null
sudo tail -n 100 /var/log/apache2/access.log 2>/dev/null

# CentOS 계열 Apache
sudo tail -n 100 /var/log/httpd/error_log 2>/dev/null
sudo tail -n 100 /var/log/httpd/access_log 2>/dev/null

# Nginx 가능성
sudo tail -n 100 /var/log/nginx/error.log 2>/dev/null
sudo tail -n 100 /var/log/nginx/access.log 2>/dev/null
```

- 위 중에서 **실제로 존재하는 로그 파일의 tail 결과**를 복붙해줘.  
- 특히 **현재 시각 근처의 에러**(Too many connections, rate limit, upstream 오류, 디스크 풀 등)를 같이 보고 판단할 수 있음.
